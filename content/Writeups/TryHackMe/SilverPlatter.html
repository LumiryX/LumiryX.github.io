Mission Scenario

Think you've got what it takes to outsmart the Hack Smarter Security team? They claim to be unbeatable, and now it's your chance to prove them wrong. Dive into their web server, find the hidden flags, and show the world your elite hacking skills. Good luck, and may the best hacker win!

But beware, this won't be a walk in the digital park. Hack Smarter Security has fortified the server against common attacks and their password policy requires passwords that have not been breached (they check it against the rockyou.txt wordlist - that's how 'cool' they are). The hacking gauntlet has been thrown, and it's time to elevate your game. Remember, only the most ingenious will rise to the top.

May your code be swift, your exploits flawless, and victory yours!

Have to obtain:

  • User Flag
  • Root Flag

Exploitation

Caido

Caido is pretty much same app as Burp Suite but Caido dont have rate limit for bruteforce attack. I will use Caido to save some time. Learn more about caido: https://caido.io/

Once everything is set up, we hit the Run button to see whether any password stands out.

We had no success using rockyou.txt Lets try another trick. Let's scrape the website and extract all words into a custom wordlist, which we use for bruteforcing password.

For this purpose we can use cewl tool. You can read more about this here: https://github.com/digininja/CeWL

Cewl

You can download this tool here: https://github.com/digininja/CeWL/releases/tag/5.2 Then run this command to unzip file: unzip CeWL-5.2.zip

When we have unzipped file move into ceWL directory and run this command:

cewl http://silverplatter.thm > custom_password.txt

This command will scrape the website and add the words into custom_password.txt file.

Then use this file as earlier to bruteforce password for name scr1ptkiddy.

Now as we can see one word took much longer time then others and is longer then others.

Which telling us this can be valid password.

HTTP (8080)

On this webpage we have an unread message. When we open we can see in the URL there is ID for the message. Which suggests IDOR vulnerability. Since we have just one message and we have ID=5 which telling us this is a global parameter using for all users on this website.

When we change the ID=6 we get a SSH credentials for tim user.

SSH (22)

These credentials are valid. We are now logged in as the tim user. Inside /home/tim directory we found /user.txt file. Which is our flag!

Privilege Escalation

But we have no luck with it.

After checking /etc/passwd. We know our root user is Tyler.

We are in the adm group.

We can do a small trick and check all the files if it doesn't includes password. Move into /var/log directory.

We can spot the following line. This line telling us the POSTGRES_PASSWORD.

Also as we know the Tyler is a root user.

Key Findings:

- IDOR vulnerability leading to obtain valid credentials
- Weak operational security, exposing credentials in logs
- Successfull privilege escalation via reused credentials

Attack Path Summary

1. Service enumeration revealed web application on port 8080
2. Username identified via OSINT from website
3. Password obtained through custom wordlist brute-force
4. IDOR vulnerability exposed SSH credentials
5. Log file analysis revealed privileged credentials
6. Credential reuse allowed root access
